react-generic-user

Generic user sessions and login components.

src.zip app.zip en de fr

Project status

Use case

Everything a React application needs around a logged-in user, without tying you to a backend or a router: You implement how to check a session, log in and log out, the library keeps the session state, offers hooks to read it and provides components to protect content and to log in. The state lives either in Redux or in a React context, routing works with any library offering a redirect component and a location hook, e.g. React Router.

Features included:

  • Session state with "authenticated", "authenticating", "deauthenticating" and the user's data.
  • Hooks "useUser", "useHasRole" and "useIsAdmin".
  • "Authenticated" component which checks the session and redirects to the login page if needed.
  • Ready to use "Login" form based on react-input-material.
  • Remembers the initially requested page to return to after login (Redux session).
  • Playwright harness for end-to-end tests of the login form.

Installation

npm install react-generic-user clientnode core-js react react-generic-tools

Depending on the parts you use, add "@reduxjs/toolkit" and "react-redux" for the Redux session as well as "react-input-material", "@rmwc/button" and "react-dom" for the components.

Session with Redux

Provide three functions talking to your backend. "authenticate" checks an existing session, e.g. via a cookie, and "login" checks credentials. Both return the user's data, which needs at least a "name" and optionally "roles", or "null" if not authenticated. "logout" returns whether it succeeded:

import {configureStore} from '@reduxjs/toolkit'
import {useLocation} from 'react-router'
import sessionFactory from 'react-generic-user/redux'

export const {slice, useHasRole, useIsAdmin, useUser} = sessionFactory(
    {
        authenticate: async () => (await api.getSession())?.user ?? null,
        login: async ({login, password}) =>
            (await api.login(login, password))?.user ?? null,
        logout: async () => (await api.logout()).ok
    },
    // Optional: Remembers the initially requested location.
    {useLocation}
)

export const store = configureStore({reducer: {user: slice.reducer}})

The slice has to be registered under the key "user". Wrap your application in the "Provider" of "react-redux" as usual. "useUser()" then returns "session", "authenticate", "login" and "logout".

Session with a React context

Without Redux the session lives in a context. "authenticate" and "login" resolve with the user's data or reject if no user is authenticated. "logout" resolves with whether it succeeded:

import sessionFactory from 'react-generic-user/context'

export const {UserProvider, useHasRole, useIsAdmin, useUser} =
    sessionFactory({authenticate, login, logout})

export const Root = () => <UserProvider>
    <Application />
</UserProvider>

"UserProvider" accepts "options" with "onAuthenticate" and "onDeauthenticate" callbacks.

Roles

"useHasRole('editor')" or "useHasRole(['editor', 'reviewer'])" is "true" if the user has all given roles. "useIsAdmin()" checks for the role "_admin".

Components

Create the components once with your "useUser" hook and your router's redirect component and location hook:

import {Navigate, Route, Routes, useLocation, useNavigate} from 'react-router'
import componentFactory from 'react-generic-user/components'
import 'react-generic-user/components.css'

const {Authenticated, Login} =
    componentFactory(useUser, {Redirect: Navigate, useLocation})

export const Application = () => {
    const navigate = useNavigate()
    const {session} = useUser()

    return <Routes>
        <Route
            path="/login"
            element={<Login onSuccess={() => {
                navigate(session.initialRequestedLocation ?? '/')
            }} />}
        />
        <Route
            path="*"
            element={
                <Authenticated fallbackLocation="/login">
                    <Dashboard />
                </Authenticated>
            }
        />
    </Routes>
}
  • "Authenticated" checks the session on first use, shows "loadingFallback" meanwhile and redirects to "fallbackLocation" if not authenticated. "children" may be a function receiving "user" and "location".
  • "Login" renders name and password fields with validation and status messages. Customize it via "loginProperties", "passwordProperties", "buttonProperties", a status render function as "children" and the callbacks "onSubmitted" and "onSuccess".

End-to-end tests

The harness locates the login form's elements for Playwright:

import loginHarness from 'react-generic-user/harness'

const {stable: {loginButton, nameInput, passwordInput}} = loginHarness(page)

await nameInput.fill('name')
await passwordInput.fill('password')
await loginButton.main.click()
